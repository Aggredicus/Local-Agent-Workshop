Evidence contract & fair-comparison rules

A comparable group requires the same task, hardware, evaluation method, generation configuration and evidence type. Mixed groups are deliberately split, not ranked together. Sample sizes and missing metrics remain visible.

Measured runs require an evidence_ref. A declaration alone cannot prove that data was measured: retain raw outputs, seeds, model hashes, prompts, task sources and calibration settings externally. Hardware/environment differences and evaluation criteria can invalidate conclusions.

Expected JSON: {"schema_version":"0.1","runs":[{"run_id":"...","model_id":"...","task_id":"...","hardware_id":"...","evaluation_id":"...","config_id":"...","evidence_type":"measured","evidence_ref":"reports/raw/run.json","samples":10,"metrics":{"latency_ms":120,"name_integrity_rate":1}}]}.

Quality gate interpretation

Name and number integrity measure exact protected-fact preservation on the chosen benchmark tasks; they do not prove that a plan is semantically correct. Never deploy a failed critical-fact plan. A pass also requires independent source validation and domain tests.
